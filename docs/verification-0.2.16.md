# 0.2.16：后台额度刷新与指定账号测试

日期：2026-10-12。基于 0.2.15 `6a0713e`，保留此前模型探查、凭证管理和缓存功能。

## 变化

- Rust 单后台定时器每 300 秒刷新支持账号的额度，包括停用账号；应用启动先恢复缓存、不立即查额度。隐藏主窗口/菜单栏仍继续；断开不查询，忙碌跳过本轮。复用原有串行刷新及缓存，失败继续显示上次成功数据与时间，并记录失败状态。
- 菜单栏、探查优先紧凑列表和凭证卡片新增试管图标。点击固定该账号与当时选定的型号，三次串行采样，前端工作线程分析；面板切换不取消。结果经 Rust 状态同步到两个窗口，重启不保存测试边框。
- 通过 CLIProxy 管理代请求的 `auth_index` 与 `$TOKEN$` 占位符执行，Token 只由服务注入；不读认证文件、不临时停用其他账号、不修改 CLIProxy。固定厂商端点适配 Codex、Claude、Grok、Gemini CLI、Antigravity OAuth；启用账号的原始型号必须同时出现在该账号目录与厂商定义中；停用账号实时目录被 CLIProxy 移除，因此只核对厂商原始型号，实际权限由厂商响应确认。别名及未支持类型拒绝执行。
- 每次付费采样前重新核对账号，失败或回答截断停止后续请求。结果应用前再次核对，换号/读取失败/旧轮次不着色；正常 OAuth 续期不误判。完成三份有效回答、参考校准可用、型号可映射且第一名库内权重至少 80% 时，匹配为绿框，不匹配为深红框，其他情况中性。切换型号隐藏不相关结果，切回恢复。
- 增强三套明暗主题的 5h/1w 色差；错误提示内距 12px × 16px，与结果区保留间距。紧凑行允许收缩，400px 菜单栏开关完整可见；测试边框在额度填充上方完整绘制。

## 接口依据与限制

采用 [CLIProxy 官方管理接口文档](https://help.router-for.me/management/apiv8) 与本地 CLIProxy 公共源码核对：管理代请求按 `auth_index` 找凭证，找不到凭证或 Token 时拒绝替换；普通 `/v1/chat/completions` 不提供同等的公开固定凭证参数。没有使用未经证实的自定义请求头。

普通自动探查仍使用 `/v1/chat/completions`，支持服务实际目录中的别名和前缀；指定账号测试使用独立固定端点，不继承服务的自定义路由/模型重写。Google 项目标识缺失时仅复用已有只读 `loadCodeAssist`，不自动开通项目。各厂商真实兼容性仍待用户实际使用验证。

80% 是 UI 着色门槛，不是校准过的接纳阈值或准确率。指纹参考库为闭集，不能认证服务身份；库外型号、低权重、样本不足、请求失败均不得红绿误报。完整应用退出会结束后台任务，未新增系统服务。
