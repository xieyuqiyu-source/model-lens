# 0.2.22：CPA 本地与远端版本对照

2026-10-14，基于 0.2.21 `b955366`。

## 变更

- 本机 CLIProxy 弹窗显示磁盘编译程序的 Go VCS 提交号、当前跟踪分支远端提交号，另保留源码 HEAD、分支与核对时间。不是 GitHub Release 版本，也不代表运行中映像核验。
- 打开弹窗、手动检查及管理操作完成后获取指定远端分支引用；不自动合并源码或执行 CPA。版本检查与应用更新互斥，忽略前端过期响应。
- 源码/干净构建/远端一致才显示已同步；区分落后、领先、分叉、本地修改和待编译。远端失败或分支被删除时旧引用仅供参考，不能误报最新。
- 更新编译和重启成功后共享按程序路径区分的成功结果，弹窗重新打开仍可见；版本自动重新核对。失败不会生成新的成功记录。
- 编译暂存放在源码仓库外，避免程序位于仓库根目录时 Go 将自身暂存产物计为源码修改。

## 验证

- 94 项 Rust 测试通过，包含临时 Git 仓库的同步、远端新增、仅源码更新、脏工作区、领先、分叉、远端失效、删除远端分支、游离 HEAD；保留本地源码不被检查操作修改。
- 临时 Go 项目实际编译检查 vcs.modified=false，未知或脏构建不能显示最新；合成服务生命周期回归通过。测试监听端口避开并行 HTTP 客户端的临时端口区间，消除启动端口竞争。
- WebKit / Chromium 合成 IPC 验证双版本、待编译、检查失败、落后数量、更新成功自动刷新，以及原有启停、路径折叠、命令日志和安装表单。已检查截图，弹窗间距正常。
- `pnpm test:ui` 25 项通过，`pnpm check` 通过。双浏览器凭证分组及 CPA 动作回归通过。
- 独立代码复核发现并修复远端删除分支旧引用误报、编译暂存污染 VCS 元数据。
