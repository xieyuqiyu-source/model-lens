# ModelLens · 模型透镜

面向 macOS 与 Windows 的轻量桌面工具，将模型指纹探查、CLIProxy 服务管理、凭证与额度查看放在一个窗口中，并提供菜单栏／系统托盘快捷面板。

> **状态：产品设计与技术方案讨论阶段。** 已完成界面预设计；尚无客户端源码、可运行程序或安装包。下文功能与技术栈为开发计划，不代表已经实现或通过兼容性测试。

## 产品功能

以完整窗口为主，菜单栏／托盘作为快捷入口。独立运行，不依赖 DSH 宿主或 DevDock，不另建云端管理服务或平台账号体系。

| 模块 | 已确认的产品方向 |
| --- | --- |
| 主窗口 | 探查优先／凭证优先切换；另一侧保留简要信息与快捷操作 |
| 模型探查 | 自动采样、手动输入同等重要，记住上次模式；以当前结果为主，历史为次级入口 |
| 手动检测 | 三条提示词默认折叠，可展开、复制；可粘贴任意外部模型回答，不受当前模型选择限制 |
| 自动检测 | 指定模型和凭证，单个检测或逐个串行批量检测，支持取消 |
| 服务管理 | 应用启动时自动启动受管 CLIProxy；提供启停入口及启动中、运行中、停止、失败状态 |
| 凭证管理 | 厂商图标、英文账号名、启用开关、JSON 凭证导入、单独检测 |
| 额度卡片 | 可获得的 5h／1w 剩余额度、重置时间、重置次数、凭证到期时间，单个／全部刷新 |
| 菜单栏／托盘 | 顶部同一行放服务状态和模型选择；每个凭证一行，支持单个和串行批量检测 |

展示约定：

- 主窗口详情同时展示 5h、1w；菜单栏每行只显示一条，有 5h 显示 5h，否则显示可用的 1w。
- 5h 用浅绿色、1w 用深绿色；绿色宽度表示**剩余额度**。
- 厂商、套餐和凭证类型的字段可能不同。缺失数据显示「未提供」，不当成 0%。
- 重置时间、凭证到期和套餐到期是不同概念，不相互代替；刷新时间及过期缓存状态要明确。
- 重置次数需有明确来源和统计口径，否则显示「暂无记录」，不根据倒计时猜测次数。
- 对勾表示参考指纹匹配；检测只能比较参考库内候选，不能证明模型身份，也不能把相似度直接称为身份置信度。

## 平台支持计划

Apple Silicon 指 M 系列芯片的 Mac。首版建议分别发布三个架构的安装包：

| 平台 | 架构 | 计划产物 | 当前状态 |
| --- | --- | --- | --- |
| macOS Intel | x86_64 | Intel 版 .dmg | 未构建、未验证 |
| macOS Apple Silicon | arm64 / aarch64 | Apple Silicon 版 .dmg | 未构建、未验证 |
| Windows Intel / AMD | x86_64 | NSIS .exe 安装包 | 未构建、未验证 |

建议将 macOS 13+、Windows 11 x64 作为首批验收范围；Windows 10 22H2 作为兼容候选，是否承诺支持由实机测试决定。Windows ARM64、Linux、移动端不列入首批交付。

最低系统版本最终取决于桌面框架、CLIProxy 固定版本和系统 WebView 的共同要求。Windows 使用 WebView2，安装程序需处理其缺失情况，不能承诺所有机器都无需安装运行组件。

## 技术方案建议

**建议组合：Tauri 2 + React + TypeScript + Vite，Rust 负责桌面能力，CLIProxy 作为独立子进程。** 讨论确认后再初始化工程，当前不引入依赖。

| 层次 | 建议选择 | 职责 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 / Rust | 生命周期、原生窗口、菜单栏／托盘、进程管理、受控文件读写和网络请求 |
| 界面 | React + TypeScript + Vite | 主窗口、快捷面板、凭证卡片、模式切换与交互状态 |
| 视觉系统 | CSS 变量 + 小型自有组件 | 还原 09A 的字体、间距、图标、圆角和阴影；复杂控件按需采用无样式组件基础 |
| 代理服务 | CLIProxyAPI 独立二进制 | 模型转发与凭证管理；按平台、架构打包 |
| 探查分析 | 可独立测试的 TypeScript 模块 | 核对许可与依赖后复用已有算法和参考数据；大计算按需放入 Worker |
| 本地状态 | 应用数据目录内的小型配置文件 | 偏好、窗口状态、非敏感元数据；历史需求扩大后再考虑 SQLite |
| 敏感信息 | Rust 侧系统安全存储适配 | 管理密钥使用 macOS Keychain／Windows 凭据存储；具体库在工程阶段验证 |
| 构建发布 | GitHub Actions + GitHub Releases | 按目标系统构建、测试、签名和发布 |

界面通过有限的 Tauri 命令调用 Rust；Rust 管理 CLIProxy 并调用管理接口。主窗口和菜单栏共用服务状态与任务队列，不重复执行任务。界面不持有长期管理密钥，也不获得任意 shell 执行权限。

Tauri 使用系统 WebView，适合轻量工具，但两端渲染环境不同，字体、阴影、滚动和透明效果需分别验收。体积、启动速度和内存占用必须包含 CLIProxy 后实测，不提前承诺数字。

自定义菜单栏额度面板采用定位到托盘图标附近的小窗口，原生菜单提供打开主窗口和退出。系统磨砂效果作为可降级增强，核心布局不依赖特定系统的玻璃 API。

参考官方文档：[架构](https://v2.tauri.app/concept/architecture/)、[Vite 集成](https://v2.tauri.app/start/frontend/vite/)、[系统托盘](https://v2.tauri.app/learn/system-tray/)、[外部二进制](https://v2.tauri.app/develop/sidecar/)、[Windows 安装程序](https://v2.tauri.app/distribute/windows-installer/)、[macOS 签名](https://v2.tauri.app/distribute/sign/macos/)。

## CLIProxy 集成

以下为实现约定，尚未执行，也未操作本机现有服务：

1. 参考 DevDock 的管理体验；发布版运行随包提供的固定版本二进制，用户无需安装 Go、Node.js 或执行开发脚本。
2. 使用独立数据目录和本机回环地址，不自动改写已有 CLIProxy 配置，不扫描或导入现有认证目录。
3. 启动受管进程并检查就绪；端口冲突、启动失败、进程退出时显示原因，不结束占用端口的其他进程。
4. 关闭主窗口后保留菜单栏／托盘；明确退出应用时取消本应用任务并停止本应用启动的服务，不接管外部服务。异常退出后的残留进程处理需单独验证。
5. 管理密钥不出现在前端持久化、日志、命令行参数或公开配置中；前端只获取展示所需的账号元数据。
6. 只处理用户主动提交的 JSON，校验格式和大小，通过管理接口新增，不覆盖已有文件；成功后清空输入，失败时给出明确结果。
7. 单凭证检测必须能够证明请求仅使用该凭证。先验证上游请求级选择能力；若不支持则设计隔离方案，不把自动轮换当成指定凭证，也不随意关闭其他账号影响并发请求。
8. 批量检测串行执行，支持进度、取消、错误状态。取消后的在途请求是否已计费以服务端为准。
9. 额度、重置次数和到期字段逐厂商核对，没有统一字段的部分允许缺失，不根据设计稿伪造数据。
10. 发布前固定上游来源、版本、校验值，核对许可及各架构构建；不执行来源不明的更新二进制。

上游候选：[CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)。最终集成版本、凭证选择能力和额度字段映射尚未锁定。

## 数据与隐私

- 指纹分析计划在本地完成；自动检测会向所配置的模型服务发送提示词并可能产生费用。刷新额度也可能访问服务商接口。
- JSON 凭证由受管 CLIProxy 使用和保存；这不等于所有上游认证文件都会被系统钥匙串加密。需核对上游存储方式并限制数据目录权限。
- 不将真实凭证、API Key、令牌、认证 JSON、用户测试内容或个人路径提交到仓库或写入日志。
- 默认不增加遥测、云同步或账号系统。偏好与凭证分开保存，错误信息脱敏。
- 不默认保存完整模型回答；历史保存内容和清理策略在实现历史入口前明确。

## 开发与验证

### 获取仓库

```sh
git clone https://github.com/xieyuqiyu-source/model-lens.git
cd model-lens
git pull --ff-only
```

当前仅包含 README、忽略规则和 docs/images 中的预设计图片。**尚无 package.json、Rust 工程、测试或构建命令。** 克隆仓库不会安装客户端或启动服务。

初始化工程时锁定 Node.js、pnpm、Rust 与 Tauri 版本，提供可重复运行的依赖安装、开发、检查、测试和打包命令。macOS 与 Windows 按 [Tauri 前置要求](https://v2.tauri.app/start/prerequisites/) 分别准备构建环境。

计划保持单仓库、单应用，按功能组织前端组件与状态，网络／桌面调用和视图分离；Rust 按进程管理、CLIProxy 接口和本地存储分模块。

发布前需验证：

- 分析：固定参考样本、异常输入、候选排序、结果解释。
- 凭证：导入校验、重复导入、缺失字段、过期缓存、刷新失败。
- 任务：指定凭证路由、串行顺序、取消、超时、失败恢复、并发互斥。
- 进程：端口冲突、重复启动、启动失败、关闭窗口继续运行、退出清理、异常退出。
- 界面：09A 样式、模式切换、键盘访问、减少动态效果偏好、缩放、多显示器托盘定位。
- 平台：三个架构的安装、启动、升级、卸载、签名；CI 编译成功不能代替运行验收。

开发与 CI 使用 mock 服务和合成凭证；真实模型调用、真实凭证操作须单独明确执行范围。

## 安装更新与卸载

目前没有发布客户端或安装包，请勿将设计截图误认为已发布程序。

计划通过 GitHub Releases 分发安装包。正式对外分发前安排 macOS Developer ID 签名与公证、Windows 代码签名；证书和签名配置不随仓库公开。未签名预览版必须明确标注，不能保证系统不会出现安全提示。

首版优先手动下载更新，自动更新待基础版本稳定后考虑。升级保留用户数据；卸载应用与删除本地凭证／数据分开处理，实际目录和清理方法在首个可运行版本发布时补充。当前仓库未安装任何后台进程。
